## 0. 총평

**"AI가 만든 티"가 나는 사이트는 아닙니다.** 문구가 실제 운영 경험에서 나온 진짜 카피고, 숫자가 구체적이고(14,000+ 리뷰, 51인승, 1125 Kewalo Basin), 글래스 처리도 스킬이 권장하는 "진짜 글래스모피즘"(1px 내부 보더 + inner shadow) 조건을 이미 갖췄습니다. 흔한 보라/파랑 AI 그라디언트도 없습니다.

**문제는 미학이 아니라 마감입니다.** 치명적인 건 세 가지 — `alert()` 12곳, 개인정보처리방침 부재, 키보드 접근성 구멍. 나머지는 "무게로 위계를 만들려다 전부 굵어진" 타이포와 획일적인 3열 카드 레이아웃입니다.

## 1. P0 — 치명 (리뉴얼 전에도 고칠 가치 있음)

### P0-1. `window.alert()` 12곳 — 결제 흐름 전체가 네이티브 알림창

| 위치 | 내용 |
|---|---|
| `ReservationClientPage.tsx:459,465,469,473,477` | 예약 단계 검증 실패 (투어/옵션/시간/날짜/픽업 미선택) |
| `ReservationClientPage.tsx:532,536` | **결제 오류 · 서버 통신 오류** |
| `ReservationClientPage.tsx:240,245,248` | 리뷰 등록 성공/실패 |
| `ReservationClientPage.tsx:1753` | 사진 5장 초과 |
| `app/(ko)/kr/booking/payment-success/page.tsx:23` | **결제 검증 실패** |

돈을 받는 화면에서 브라우저 기본 알림창이 뜨면 신뢰도가 즉시 떨어집니다. 특히 `:532` 결제 오류와 `payment-success:23` 검증 실패는 **고객이 돈이 나갔는지 아닌지 불안한 순간**에 뜨는 창입니다.

**조치**: 폼 검증은 해당 필드 하단 인라인 에러로, 결제/통신 오류는 페이지 내 에러 배너(재시도 버튼 포함)로. `react-hook-form`이 이미 들어와 있어 인라인 에러는 추가 의존성 없이 가능합니다.

### P0-2. 개인정보처리방침 · 이용약관 링크 **0개**

전 페이지 검색 결과 privacy / 개인정보 / terms / 이용약관 링크가 **하나도 없습니다.**

Stripe로 한국 고객에게 결제를 받고, 이름·이메일·연락처·숙소 주소를 수집하며, 구글 Places로 위치를 조회합니다. 개인정보처리방침 미고지는 디자인 문제가 아니라 **법적 노출**입니다.

**조치**: 전역 푸터에 `개인정보처리방침` · `이용약관` 추가. 취소·환불 규정은 이미 훌륭하게 정리돼 있으니(FAQ + 예약 취소 플로우) 그것과 같은 위치에 묶으면 됩니다.

### P0-3. 키보드 접근성 — 컴포넌트 4개에 포커스 표시 전무

| 컴포넌트 | `focus-visible` / `focus:ring` |

**조치**: 전역 `:focus-visible` 스타일 1개 정의 + 각 클릭 가능한 `div`를 `button`으로 교체. PRD §9에 이미 기준으로 잡혀 있습니다.

## 2. P1 — 높음 (리뉴얼에서 교정)

### P1-1. 타이포 위계가 "굵기"로만 만들어짐

실측한 weight 분포:

| weight | 사용 횟수 |
|---|---|
| `font-bold` (700) | **75** |
| `font-medium` (500) | 39 |
| `font-black` (900) | **33** |
| `font-extrabold` (800) | 7 |
| `font-semibold` (600) | **5** |

700 이상이 **115회**, 중간 무게(500–600)가 44회. 화면 대부분이 굵습니다. 다 굵으면 아무것도 강조되지 않습니다.

**조치**: 위계를 **크기 + 색 + 여백**으로 옮기고 weight는 3단(400 본문 / 600 소제목 / 800 대제목)으로 축소. PRD §7.4 타이포 스케일이 이미 크기 기반이라 그대로 맞물립니다.

### P1-2. `text-wrap` 미적용 — 한국어 제목 고아 단어

고객 사이트 전체에 `text-balance` / `text-pretty` **0곳**. 한국어는 `break-keep`과 결합했을 때 마지막 줄에 한 단어만 떨어지는 현상이 특히 눈에 띕니다.

**조치**: 모든 `h1~h3`에 `text-wrap: balance`, 본문에 `text-wrap: pretty` 전역 적용.

### P1-3. 숫자에 `tabular-nums` 없음

가격·인원·잔여석이 비례 폰트로 렌더됩니다. 어드민(`settlement/page.tsx`)에는 적용돼 있는데 **고객 화면에는 없습니다.** 날짜 선택 시 잔여석 숫자가 바뀔 때마다 폭이 흔들립니다.

**조치**: 가격·정원·날짜 숫자에 `font-variant-numeric: tabular-nums`.

### P1-4. 3열 균등 카드 — 스킬이 "가장 흔한 AI 레이아웃"으로 지목

- 투어 카드 `lg:grid-cols-3`
- 벤토 5카드 (4/4/4 + 6/6)
- 후기 카드 3열

세 섹션이 연속으로 같은 리듬입니다.

**조치**: 벤토는 이미 비대칭(3+2)이라 살리고, **투어 카드를 주력 1개 크게 + 나머지 2개 작게**로 바꾸는 걸 권합니다. 실제로 매출 대부분이 "와이키키 거북이 스노클링" 한 상품에서 나오는데 지금은 프라이빗·선셋과 동등한 크기로 취급됩니다. 디자인 문제이자 **전환 문제**입니다.

### P1-5. 그림자가 순수 검정

`shadow-[0_15px_35px_rgba(0,0,0,0.05)]` 계열이 반복됩니다. 바다색 배경 위에 중성 검정 그림자가 얹히면 탁해 보입니다.

**조치**: `rgba(2,132,199,0.10)` 같은 sky 계열 틴트로 교체. PRD §6.4 `--shadow-card` 값 수정 대상.

### P1-6. 캐러셀 2개가 연달아 배치

고객 리뷰 가로 캐러셀 바로 아래 구글 리뷰 캐러셀. 스킬이 "3-card carousel testimonials"를 흔한 패턴으로 지목하는데, 여기선 **두 번 연속**입니다. 모바일에서 가로 스와이프 영역이 세로로 두 번 나오면 스크롤이 걸립니다.

**조치**: PRD §5.3대로 후기 전용 페이지에서는 **그리드**로, 홈에서는 **발췌 6개 + 더보기**로. 캐러셀은 구글 리뷰 하나만 남깁니다.

### P1-7. 라운드가 전부 동일

`rounded-[2rem]` / `rounded-[2.5rem]`이 카드·패널·섹션에 무차별 적용. 안쪽 요소와 바깥 컨테이너가 같은 곡률이면 층위가 안 보입니다.

**조치**: PRD §6.4에 이미 4단계(`--radius-input` 12 / `--radius-card` 24 / `--radius-hero` 40 / pill)로 잡혀 있습니다. 그대로 적용하면 해결.

## 4. ✅ 잘 하고 있는 것 (건드리지 말 것)

1. **문구가 진짜다.** lorem ipsum·"Elevate"·"Seamless" 류 AI 상투어 0건. FAQ 30문항이 실제 고객 질문에서 나왔습니다

3. **액센트 컬러 1개** (sky/blue 계열). 스킬이 지적하는 다색 남용 없음
4. **AI 그라디언트(보라-파랑) 없음**
5. **글래스 처리가 제대로다.** `inset 0 0 20px rgba(255,255,255,.6)` + `border-white/60` — 스킬이 말하는 "진짜 글래스모피즘" 조건 충족
6. **빈 상태 있음** — "첫 번째 리뷰의 주인공이 되어주세요!"
7. **404 페이지 있음** — 한/영 병기 + 홈 복귀 버튼
8. **호버 상태 충실** — `hover:-translate-y-2`, `hover:scale-110`, transition 200–500ms

## 6. 권장 실행 순서

스킬의 Fix Priority(위험 대비 효과 순)를 이 프로젝트에 맞춘 것:

1. **`alert()` 제거 + 인라인 에러** — 결제 신뢰도. 리뉴얼과 무관하게 지금 해도 됨
2. **푸터 법적 링크** — 30분 작업, 법적 노출 제거
3. **`:focus-visible` 전역 + skip-link** — 접근성 기준선
4. **토큰 도입** (`tokens.css`) — 색·그림자·라운드·타이포 (P1-1/5/7 동시 해결)
5. **레이아웃 재구성** — 투어 카드 비대칭, 캐러셀 축소 (P1-4/6)
6. **스켈레톤·파비콘·이미지 정리** (P2 전부)

1–3번은 **리뉴얼 착수 전에 따로 처리해도 되는 독립 작업**입니다. PRD Phase와 충돌하지 않습니다.
